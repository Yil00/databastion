# Changelog

All notable changes to DataBastion are recorded here.

The notes of the next release are curated by hand in the "Unreleased" section; at each release they are moved automatically under the new version, and become the GitHub release notes, see [RELEASE.md](RELEASE.md). Do not edit the released sections by hand.
The project follows [semantic versioning](https://semver.org/).

## Unreleased

### ✨ Features
- Agent: Apereo CAS Audit names the OAuth 2.0 / OIDC client of the token-only grants (`refresh_token`, `client_credentials`, `password`; [ADR-0044](docs/adr/0044-cas-token-only-grants-client-naming.md), refining [ADR-0041](docs/adr/0041-cas-connector.md) decision 7). Their token response (`OAUTH2_ACCESS_TOKEN_RESPONSE_CREATED`), a `read` of `*` since 0.5.0, is now a `read` of the registry entry whose `clientId` the preceding token request (`OAUTH2_ACCESS_TOKEN_REQUEST_CREATED`) names, as a service ticket names its service, so application-scoped policies and baselines see these grants. The agent now reads `grant_type` and `service` from the token request's `what` (never `code`, the authorization code or refresh token id, nor `scope`), and `serverIpAddress` of the token request and response records (an IP literal for the correlation key, never sent). Request and response are correlated per audit stream within 5 s (at most 1024 pending requests, in memory only) by client address, server address and user agent; a response is named only when every pending request of its key selects the same entry (and, for `client_credentials`, its `who` is the client id), `*` otherwise. `authorization_code` and the device grant stay `*`; audit levels are unchanged; no protocol change. Do not exclude `OAUTH2_ACCESS_TOKEN_REQUEST_CREATED` from the CAS audit. Losses the agent sees fail towards `*`: an evicted pending request or a dropped audit line taints the correlation for 5 s around it, and a skipped registry file disables the client match. Residual risk: a token request record lost where the agent cannot see it (a restart between request and response) can attribute a response to another client of the same address and user agent within 5 s. Details: [docs/08-engine-capabilities.md](docs/08-engine-capabilities.md#apereo-cas)

### ⚡️ Performance
- Agent (MySQL / MariaDB): the CAS store guard's heartbeat check no longer sends one `information_schema.COLUMNS` query per 900-byte chunk of the name list (3 with the built-in names, up to 67 with long `cas_stores` lists). It reads the table names once from `information_schema.TABLES` (no table definition opened), matches the name keys in the agent, and sends a column query only for each name key present. Measured at 5 000 tables with three 64-name `cas_stores` lists: 1.00 s → 0.24 to 0.29 s on MySQL 8.4, 1.11 s → 0.50 to 0.66 s on MariaDB 11.4 (built-in names: 0.16 → 0.22 s and 0.41 → 0.48 to 0.53 s, one more statement); the same stores are recognized. The Audit stream recognizes the new statements by their exact text, as before; the column-shape query is unchanged and is the remaining cost (about 0.1 s per 1 000 tables on MariaDB) ([docs/08](docs/08-engine-capabilities.md#cas-store-guard-postgresql-mysql--mariadb-mongodb-openldap))

### 🐛 Bug Fixes
- **Security fix**, agent (MySQL / MariaDB Audit, security review of #181, High): a statement text cut by the source with no table record is reported as a read of `*`, always (never dropped by `min_rows`), and never left out as the agent's own. Before, padding (spaces, a `-- …` comment, repeated tokens) could push a `UNION ALL SELECT … FROM hr.customers` past the cut, and a text whose visible part read only `information_schema` (or `SELECT 1`) produced no event, from any account, the agent's included: on `server_audit` with `QUERY` events only (cut at `server_audit_query_log_limit`) and on `performance_schema` (`SQL_TEXT`, and a `DIGEST_TEXT` filled by token padding). The agent's own Discovery samples are now split into column batches so that every sampling statement stays within 900 bytes and is never cut at the default limits; on MySQL, `SHOW GRANTS … USING` with many long role names is split too (below). The CAS store guard's table list is bounded (`LIMIT 1000001`, `privilege.not_evaluated` beyond 1 000 000 tables), and a ticket table readable through a column grant only is tested on MySQL 8.4 and MariaDB 11.4 ([docs/08](docs/08-engine-capabilities.md#statement-text-and-passwords))
- **Security fix**, agent (MySQL / MariaDB `performance_schema` Audit, security review of 914c9d2, N1, High): a digest cut at its token storage was not seen as cut. The server stops a digest when its storage is full, and one-letter identifier padding (`WHERE a IN (a,a,a,…)`) fills a 1024-byte storage with an 895-byte digest text, with no `...` marker, so a read after the padding produced no event. The agent now reads `max_digest_length` as well as `performance_schema_max_digest_length` (a digest is cut at the smaller), estimates the storage from the digest text, reads `SQL_TEXT` for long digests and for the agent's own account, and analyzes an uncut `SQL_TEXT` instead of the digest; a possibly cut digest without an uncut `SQL_TEXT` is a read of `*`, always reported. Discovery: each column batch of a wide table gets a share of the 32 MiB per-table budget in proportion to its columns, the later batches run after a stopped one, and columns sampled short or not at all count under `skipped_limit` (N2); the extra batches of one scan of a table are no longer reported as the agent's reads: they hold single-use, exact-text credits shared with the target's Audit stream (N3) ([docs/08](docs/08-engine-capabilities.md#statement-text-and-passwords))
- **Security fix**, agent (MySQL `performance_schema` Audit, security review of 09e93da, R1, High): with a client character set such as gb18030 (`SET NAMES gb18030`, open to any account), MySQL applies its text and digest limits to the client's bytes (`Ā`: 4 bytes stored, 2 read), so a cut `SQL_TEXT` or a full digest could look whole and hide a read after its padding. The agent now measures texts as stored in the worst case (4 bytes per non-ASCII character), takes a `SQL_TEXT` ending in `...` as cut, and analyzes a whole `SQL_TEXT` together with a whole digest, the event taking the tables and signals of both. The own-session `SQL_TEXT` rule now needs the agent's user name and client host; Discovery sampling credits are granted only while the target's Audit stream runs and expire after two polls plus the statement timeout (30 s to 15 min). Discovery sizes its sampling batches by that stored measure too, so that its own statements on tables with non-ASCII column names are never taken as cut. Other statements with many non-ASCII characters can now be reported as reads of `*` ([docs/08](docs/08-engine-capabilities.md#statement-text-and-passwords))
- **Security fix**, agent (MySQL / MariaDB Audit, #168 review L2): a `LOAD_FILE(…)` call is reported. It reads a file on the database server (with the `FILE` privilege and a permissive `secure_file_priv`, table files included), and a table-less `SELECT LOAD_FILE(…)`, `SET @x = LOAD_FILE(…)` or `DO LOAD_FILE(…)` produced no event on any source. It is now code that runs out of sight, like a stored function call: a read of `*` (with the tables the statement names), always reported (never dropped by `min_rows`), never left out as the agent's own; a session `SET` or an allow-listed statement (`SHOW … WHERE`) holding it is no longer quiet. The name is matched on code (plain, backquoted, double-quoted, in executable comments, digests included) and, in a text that does not lex, by a scan of the whole text ([docs/08](docs/08-engine-capabilities.md#statement-text-and-passwords))
- **Security fix**, agent (MySQL / MariaDB Audit, security review of #184): a statement text the source cut is a read (or write) of `*` too, always reported and never the agent's own, **even with table records**: the records do not name a server file that a `LOAD_FILE` call padded past the cut read (M1). A call of a function whose name holds a non-ASCII character (`LOAD_FÍLE(…)`, full-width `ＬOAD_FILE(…)`: stored function lookups on MySQL 8.4 and MariaDB 11.4, never `LOAD_FILE`) is code that runs out of sight (M2). The raw scans of texts that do not lex skip vertical tabs and form feeds before `(` (L1). A server-side `LOAD DATA INFILE` / `LOAD XML INFILE` (without `LOCAL`) also reads `*`, always reported (L2). A word after `@` is never the statement an `EXPLAIN` runs: `EXPLAIN FORMAT=JSON INTO @select ANALYZE DELETE …` was quiet (L3) ([docs/08](docs/08-engine-capabilities.md#statement-text-and-passwords))
- Agent (MySQL / MariaDB Audit, #168 review L3): an `EXPLAIN` / `DESCRIBE` / `DESC` of more than 32 tokens with no statement keyword in its first 32 (not valid SQL today) is never quiet: reported against `*`, always, never the agent's own. Before, such a text with `ANALYZE` past the bound was quiet
- Agent (MySQL): `check()` splits the `SHOW GRANTS FOR CURRENT_USER() USING …` role list over several statements of at most 900 bytes each (as `server_audit` logs them and as `performance_schema` may store them) and takes the union of the privileges they show, so that an account with many long role names is no longer cut in the audit logs and reported at every heartbeat as the agent's read of `*`. MySQL combines role privileges as a union, partial revokes included, and the agent ignores `REVOKE` lines, so the evaluated privileges are unchanged (security review of 914c9d2, Low; [docs/08](docs/08-engine-capabilities.md#the-agents-own-account-1))
- Agent dependencies: `base64` 0.23.1 in `databastion-core` (agent secret bodies) and `connector-mongodb` (SCRAM), with the fuzz harness lockfile updated too (replaces Dependabot #174, which left `agent/fuzz/Cargo.lock` stale and failed the `--locked` fuzz and cargo-deny jobs). No code change was needed: the engines used (`STANDARD` with padding, `URL_SAFE_NO_PAD`), their alphabets and padding modes are unchanged, now pinned by fixed-vector tests; the agent still uses only the scalar `GeneralPurpose` engine. `base64` 0.22.1 stays in the graph for `reqwest`, `postgres-protocol` and `wiremock`. Its MSRV is 1.71, below the agent's 1.88
- Agent: secrets and statement texts no longer leave unwiped copies in memory on four paths (ROADMAP phase 8 follow-ups). The generated agent secret is built in a zeroizing buffer from the start (#178 review Low), and `identity.json`, the `/rotate` and `/enroll` bodies and the `Authorization` header are written into zeroizing buffers allocated once at their final length (`serde_json::to_vec` and `format!` grew theirs, freeing copies of the secret or enrollment token). CAS JSON service definitions and MySQL / MariaDB JSON audit-log records (Percona `audit_log`, `audit_log_filter`, MySQL Enterprise) are read as raw JSON values and unescaped by the agent into wiped buffers (`databastion_core::jtext`, moved from `connector-cas`), never by `serde_json` (CAS review L4, #168 review M2); same findings, `SecretForm`s, records, bounds and drop counters, checked against the former parsers by property tests. A CAS JSON definition must now be UTF-8 as a whole (a byte that is not UTF-8 in a skipped value was accepted). A CAS JSON definition that is both beyond the parser's bounds and not valid JSON is now refused as malformed (scan coverage `unsupported`) instead of as a limit (`limit`), since the whole document is checked as JSON first. The CAS YAML pre-scanner blanks single-line credential values on their key's line before `serde_yaml_ng` copies them, and computes the top-level `clientSecret` form first, including in a root mapping indented under `--- !<class>` (#169 review L2); a nested `clientSecret` and a double-quoted value with an escape the YAML parser refuses are never blanked, so blanking changes neither a `SecretForm` nor whether a file is accepted; nested credential subtrees and block scalars are not blanked yet, and are still skipped by the visitor

## [0.5.0](https://github.com/Yil00/databastion/compare/0.4.0...0.5.0) (2026-10-08)

### ⚠️ Upgrade notes
From 0.4.x: upgrade the console first, then the agents, as for every release (a console `X.Y` accepts agents `X.Y` and `X.(Y-1)`, [RELEASE.md](RELEASE.md#compatibility)). Check these points before upgrading:
- **MySQL / MariaDB Audit reports more (behaviour change, #168)**: the Audit stream now fails closed. Writes to `information_schema`, `performance_schema` and `sys` tables and audit configuration changes (`SET GLOBAL` / `SET PERSIST`, `INSTALL` / `UNINSTALL`, the `audit_log_*` administration functions, writes to `mysql.audit_log_filter` / `mysql.audit_log_user`) are reported from every account and are never dropped by the `audit.configure` minimum rows (`min_rows`). Statements that used to hide a read or a write are reported: version comments, double-quoted names (`ANSI_QUOTES`), `ANALYZE` / `EXPLAIN ANALYZE`, `SET STATEMENT … FOR`, `BEGIN NOT ATOMIC`, reads inside `SET` or `DO`. A statement outside a closed allow-list (session `SET`, `USE`, transaction statements, `SHOW`, `EXPLAIN` / `DESCRIBE` without `ANALYZE`, `LOCK` / `UNLOCK TABLES`, `FLUSH`, table maintenance, `KILL`, `DEALLOCATE PREPARE`) is reported as a read of what it names or of `*`. **Expect more events, and some events against the object `*`**: applications that write string literals in double quotes, `DO …`, `XA …`, replication commands; on MariaDB with `performance_schema` or a `QUERY`-only `server_audit` log, the agent's own Discovery samples now go through the 24 h own-account row budget (a second scan of a table within 24 h can show as a read by the agent's account); on file sources without table records, the agent's samples of a table or column whose name ends in a non-ASCII character are reads of `*` by the agent's account. Review the policies and baselines of these targets after the upgrade ([docs/08](docs/08-engine-capabilities.md#statement-text-and-passwords))
- **Policies limited to reads**: a multi-statement text whose most reportable statement is a write is a `write` event and now keeps the signals of its reads (`signature.into_outfile`, `shape.full_table_read`, `signature.mysqldump`). A policy with `event_actions: ["read"]` does not match them: add `write` to its actions, or remove the action condition
- **MySQL / MariaDB log limits**: keep `server_audit_query_log_limit` and `performance_schema_max_sql_text_length` at 1024 or more (the defaults). The CAS store guard's statements (at most 900 bytes, sent at every heartbeat) are left out of Audit only by their whole, uncut text; below that limit they are cut and reported at every heartbeat as the agent's own reads of `*` (the agent logs a warning)
- **Console worker and pg-boss 12.36 (#166)**: at its first start the 0.5.0 worker upgrades the pg-boss schema to version 44 and creates `pgboss.instance` (host name, pid, versions, pool and process figures, queue names; no connection string nor credential). This is not a console migration: the worker applies it as the runtime role, which owns the pg-boss tables, so no new grant is needed, but the worker must start with its usual database role and rights. **Back up the console database before upgrading** and keep that backup for a rollback
- **Agent `.deb`**: the systemd unit sets `LimitCORE=0`, so the agent writes no core dump (it holds database credentials). A local drop-in that sets `LimitCORE` overrides it; remove such a drop-in
- **Apereo CAS (#165)**: the CAS store guard now uses the CAS 8.0.2 ticket prefixes. A column, field or attribute holding a value that starts with `ODT`, `ODUC`, `CIBA`, `OPAR`, `SART`, `SATQ` or `STS` followed by `-<digits>-` is no longer read further (`coverage.cas_guard_tripped`), so its findings may not come back; a `CT-<digits>-` value is now dropped alone, and the rest of its column classified. CAS targets used for OAuth 2.0 / OIDC token grants now get `read` events of `*` and can move from Limited to Partial

### ✨ Features
- Agent: Apereo CAS YAML service registries (`cas.service_registry.yaml_dir`, refused before): `.yml` / `.yaml` definitions in the form CAS 8.0.2 writes (`--- !<org.apereo.cas.…>` class hints), read by the same visitor as JSON and giving the same findings. Each file is pre-scanned on its raw bytes before any YAML parsing and skipped (counted in `coverage.registry_files_skipped`) when it holds an anchor or an alias, a tag other than a class hint, a merge key, a directive, a second document, a complex key, or nesting, flow nesting, a line or token count beyond the bounds (the token bound keeps the parser's memory proportional to what the visitor accepts). Unquoted YAML integers (`phone: 33612345678`, card numbers) are classified as their text. No new dependency (`serde_yaml_ng`, already used for `agent.yaml`). Details: [docs/08-engine-capabilities.md](docs/08-engine-capabilities.md#apereo-cas)
- Agent: Apereo CAS Audit maps the OAuth 2.0 / OIDC token issuance, `OAUTH2_ACCESS_TOKEN_RESPONSE_CREATED` (verified against CAS 8.0.2 for the authorization code, `refresh_token`, `client_credentials` and `password` grants), to a `read` of `*` (CAS writes no service in that record; token values are never read), and counts it like `SERVICE_TICKET_CREATED` for the Partial level ([ADR-0041](docs/adr/0041-cas-connector.md) decisions 7 and 10): a CAS used only for OAuth / OIDC token grants now reaches Partial. An authorization code login gives two `read` events (its service ticket's and the token response's). The other OAuth / OIDC actions are counted only. Details: [docs/08-engine-capabilities.md](docs/08-engine-capabilities.md#what-is-kept)

## [0.1.0](https://github.com/Yil00/databastion/releases/tag/0.1.0) (2026-09-30)

### ⚠️ Known limitations
Details and rationale are in [docs/05-security.md](docs/05-security.md), [docs/08-engine-capabilities.md](docs/08-engine-capabilities.md) and the ADRs linked below; this list only points to them.
- **Upgrade the console and the agents together** for 0.1.0. Agent builds from before #60 cannot decode `HeartbeatResponse.accepts` ([ADR-0022](docs/adr/0022-protocol-capability-negotiation.md), consequences; [RELEASE.md § 7](RELEASE.md#7-pre-release-checklist)).
- **Audit levels differ per engine** (Full / Partial / Limited / None, reported by each target's `check()`): MySQL / MariaDB are never Full, **MongoDB is never Full**, OpenLDAP and PostgreSQL reach Full only with the prerequisites of the [matrix](docs/08-engine-capabilities.md#matrix).
- **Audit records lost while the agent is stopped** ([docs/08](docs/08-engine-capabilities.md#audit-log-files-and-failing-streams-every-engine)): the rest of a log file rotated by rename is not read; MySQL / MariaDB statements held in a rotated file are lost ([one event per statement](docs/08-engine-capabilities.md#one-event-per-statement-audit-log-files)); what `performance_schema` history no longer holds after it wrapped is lost and counted ([MySQL / MariaDB known limits](docs/08-engine-capabilities.md#known-limits-1)). A log truncated in place while the agent was stopped used to be read from the middle of its new content; this is fixed by #97 (Bug Fixes below).
- **Discovery is slow by default**: at the default 1 % duty cycle and 3600 s budget, a scan covers about 36 s of query time, so large targets show "partial coverage" and scans take about 100 times longer than unpaced ([ADR-0035](docs/adr/0035-discovery-pacing.md), [docs/08](docs/08-engine-capabilities.md#discovery-load-on-the-monitored-database-every-engine), [user guide](docs/10-user-guide.md#9-discovery-scans-and-findings)). Since #98 the console delivers one scan per agent at a time, so a full pass over N targets of one agent takes about N × the scan budget, and a scan still waiting 24 h after its request expires ([ADR-0036](docs/adr/0036-console-discovery-scan-scheduling.md)).
- **PostgreSQL statement text on the agent host**: with `pg_read_all_stats`, the agent account can read other users' raw statement text, including passwords typed as literals; `pg_stat_statements` keeps DCL passwords in clear. Nothing of it leaves the agent, but the credentials are sensitive ([docs/05](docs/05-security.md#recommended-database-accounts-read-only), [docs/08](docs/08-engine-capabilities.md#known-limits)). On `pg_stat_statements`, a holder of the agent's credentials can run the agent's allow-listed table-less statements, with any constants, without them being reported ([the agent's own account](docs/08-engine-capabilities.md#the-agents-own-account)).
- **Failed-login flood**: an attacker can keep 100 junk names above root's count, at about 100 times root's volume (visible in `auth_failures_overflowed_total`), and an events flood can evict findings from the spool down to a quarter of its bounds ([agent README](agent/README.md#failed-login-flood), [docs/08](docs/08-engine-capabilities.md#known-limits-1)).
- **MongoDB abandoned authentications** (since #100): a MongoDB authentication abandoned before any proof (result 337) gives no event, so a client that knows account names can confirm they exist and collect their SCRAM salt and iteration count without being reported; it cannot verify a password without sending a proof, and every wrong proof is reported ([docs/08](docs/08-engine-capabilities.md#known-limits-2)).
- **Records dropped by per-record isolation** reach the counters (`audit.records_dropped`, `audit_record_panics_total`) and the `agent.audit_stream_stopped` alert, not the policies; a masked "conversion failed" event is a v0.1.x item ([ADR-0032](docs/adr/0032-audit-stream-panic-isolation-and-openldap-probe-refresh.md)).
- **Carried forward**: name-normalization gaps ([ADR-0009](docs/adr/0009-name-normalization-and-item-sanitization.md), [docs/05](docs/05-security.md#masking-and-fingerprints)); OpenLDAP `check()` does not probe `userPKCS12`; e-mail notifications are plain text only; the system-alert budget holds only with the same `DATABASTION_SYSTEM_ALERTS_MAX_PER_HOUR` on every console process ([ADR-0033](docs/adr/0033-system-alert-budget.md)); webhook and e-mail consumers must escape principals ([docs/05](docs/05-security.md#alerting)).
- **Release trust**: a single maintainer approves releases ([RELEASE.md § 6](RELEASE.md#repository-configuration-one-time)).

- Deploy: fetch the agent dependencies before the release version bump (#109)

### 🐛 Agent classifiers
- Value-based column classification: birth dates, person names and postal addresses are detected without a column-name hint (age distribution, name lexicon, address structure); broader phone, IBAN, NIR, AWS key and password-hash formats; card and e-mail precision rules (checksum consistency, personal mailboxes only)
- Values are put in Unicode NFC before detection and fingerprinting: fingerprints of decomposed (NFD) non-ASCII values, e.g. accented e-mail addresses, change to those of their composed form
- The `regex` `unicode-case` feature is declared by the classifiers crate (case-insensitive patterns failed in the production build) and every pattern is compiled at agent startup
