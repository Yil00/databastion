# CONTEXT.md – DataBastion

Project context for every contributor, human or AI agent. Read it **before** any task.

## In one sentence
DataBastion is an open-source DLP (Apache 2.0) that finds sensitive data in PostgreSQL, MySQL/MariaDB, MongoDB and OpenLDAP, and Apereo CAS since 0.4.0 (*Discovery*) and detects abnormal extractions of it (*Audit*), using agents that never accept an inbound connection.

The MySQL / MariaDB Audit connector is merged (P4-B, #64; [ADR-0023](docs/adr/0023-mysql-mariadb-audit-sources-and-levels.md)): the MariaDB `server_audit` log or the Percona `audit_log` JSON log read locally (Partial, Limited without a record in the last 24 h) or `performance_schema` (Partial / Limited), never Full, no reliance on server password masks, `signature.mysqldump` and `signature.into_outfile` ([docs/08](docs/08-engine-capabilities.md#mysql--mariadb-audit)). The P4-D protocol follow-up is merged (#60): the `/events` checks and back-pressure in the contract text, the signal registry (`signals.json`), an optional `AccessEvent.bytes`, the meaning of the object `*`, closed-code `TargetStatus.notes` (`target-notes.json`), scan coverage counters, and capability negotiation of optional fields added after 0.1.0 ([ADR-0022](docs/adr/0022-protocol-capability-negotiation.md), refines ADR-0013). The console follow-up to #60 is merged (#62: `bytes` stored and shown, target notes stored and rendered, unregistered signals flagged; the P1-A escaping item is closed). Two bugs found by the Audit end-to-end test are fixed: console wake-ups in the production build (#63, `processGlobal`) and the PostgreSQL connector's own table-less statements, with pgaudit proven loaded through `pg_settings` (#65). The Audit end-to-end test is merged (#66): `pg_dump` and `mariadb-dump` from the dev clients raise an incident in 69 s and 58 s in CI, the I2 check covers the event path, and the agent's own reads are never reported. The agent follow-up to #60 is merged (#68): `TargetStatus.notes` from `check()` (including `audit.records_dropped`) and the scan coverage counters, sent only when the console lists their tokens, with the ADR-0022 decision 9 obligations (capabilities cleared, one strip-and-resend). The console rate limits are shared across console processes through PostgreSQL (#69, [ADR-0024](docs/adr/0024-shared-rate-limits.md): HMAC-keyed counters, fail closed for authentication, enrollment, rotation, logins and test sends, per-process fallback for ingest rates). The last agent follow-ups due before the phase 4 exit are merged (#70, [ADR-0025](docs/adr/0025-mysql-mariadb-role-privileges-and-heartbeat-checks.md)): a scan's terminal status waits up to 120 s for its findings batches (`scan_status_before_flush_total` otherwise); heartbeat target checks run concurrently under one 10 s deadline, one at a time per database account; MySQL / MariaDB `check()` evaluates the privileges held through roles (every applicable role on MySQL 8.0.19+, only the default role on MariaDB, never `SET ROLE`, fail closed). The end-of-phase-4 security review is done: its gates are closed by #72 (access event `ts` / `ts_last` clamped to the agent clock; dev and E2E accounts at 5 connections) and by the documentation of the per-account connection limits with Audit ([ADR-0025](docs/adr/0025-mysql-mariadb-role-privileges-and-heartbeat-checks.md) decision 11) and of the failed-login flood residual. Phase 4 is closed.

## Invariants (non-negotiable)
| # | Invariant | Source |
|---|-----------|--------|
| I1 | Agents open no inbound port; only the agent initiates connections (HTTPS 443) | ADR-0001, ADR-0004 |
| I2 | No raw sensitive value leaves the agent: masked samples + HMAC only | ADR-0003 |
| I3 | Database credentials never leave the agent host | ADR-0003 |
| I4 | The agent only reads, with a dedicated least-privilege account | 05-security |
| I5 | No network scanning: declared targets + local detection only | ADR-0006 |
| I6 | The protocol is defined by `shared/protocol/openapi.yaml`; no hand-written protocol types | 03-STACK |
| I7 | Public repository = Apache 2.0 only; no Enterprise code here | ADR-0005 |

## Glossary
| Term | Definition |
|-------|-----------|
| **Console** | Control plane: Next.js UI (`web`) + `worker` + internal PostgreSQL |
| **Agent** | Rust binary deployed close to the databases; the console's only client |
| **Connector** | Engine-specific agent module (`connector-postgres`…) |
| **Target** | A database or directory instance (for Apereo CAS: a set of local files) monitored by an agent |
| **Enrollment** | Exchange of a single-use token for an agent identity |
| **Job** | Console order fetched by the agent via long-poll (e.g. `discovery.scan`) |
| **Classifier** | Detector for a data type (`pii.email`, `pii.iban`, `secret.aws_key`…) |
| **Finding** | Discovery result: a location contains a sensitive data type |
| **Access event** | Normalized Audit result: who read what, how much, with which signals |
| **Signal** | Exfiltration indicator: `signature.*`, `shape.*`, `volume.*` |
| **Policy** | Condition → action rule applied by the worker |
| **Incident** | What a policy creates, and what the user handles |
| **Audit level** | Full / Partial / Limited / None, depending on the engine (docs/08) |
