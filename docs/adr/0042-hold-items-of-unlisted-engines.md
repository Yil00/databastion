# ADR-0042: Engine capability tokens: items of an unlisted engine are held, not stripped

- **Status**: Accepted (2026-10-04; the maintainer delegated the phase 8 technical decisions; subject to the P8-C security review of PR #137)
- **Date**: 2026-10-04
- **Refines**: [ADR-0022](0022-protocol-capability-negotiation.md) decision 9 (which stays Accepted), for the engine values gated by [ADR-0041](0041-cas-connector.md) decision 12 (Accepted; the authority for `engine.cas`), which applies the rule proposed in [ADR-0039](0039-engine-scope-expansion.md) decision 8
- **Context references**: ROADMAP P8-C, PR #137 (`feat/p8-c-protocol-cas`, commit c14c160); `agent/crates/core/src/capabilities.rs` (`engine_token`, `connector_token`, `audit_source_token`, `withhold_unaccepted_engines`, `enroll_connectors`), `agent/crates/core/src/uplink.rs` (`ResultBatch::held_back`, `ResultBatch::stripped`, `UplinkError::ItemsRejected::unknown_value`), `agent/crates/core/src/spool.rs` (`Entry::gates`, `Entry::kept_once`, `front_sendable`, `held_batches`), `agent/crates/core/src/runtime.rs` (`resend_stripped`, heartbeat building); [docs/09-agent-protocol.md](../09-agent-protocol.md#compatible-changes-and-capability-negotiation)

## Context
ADR-0022 decision 9 says what the agent does when a console rejects a gated **optional field**: it clears the capabilities and resends the items with the field stripped, because an older console accepts them without it.

ADR-0041 decision 12 (applying the rule proposed in ADR-0039 decision 8) gates something else: new **values** of the closed enums `Engine`, `Connector` and `AuditSource`, the first being `cas` and `cas_audit_log` under the token `engine.cas`. These enums have no fallback value. A console built before `cas` rejects any body naming it, and the value cannot be stripped: a finding without `Location.engine`, or an event without `source`, is not a valid item, and replacing the value would misreport the target. ADR-0022 decision 4 (send the fallback `other`) does not apply either.

Dropping such items would lose data during the very situations negotiation exists for: a rolling upgrade, a rolled-back console, or replicas that do not all list the token yet (ADR-0022 decision 8).

## Decision
1. **Heartbeats and `/enroll` leave out what cannot be stripped.** Until the console's latest heartbeat response lists an engine's token, a heartbeat leaves out the connectors, targets and detected targets of that engine, and drops the `audit_source` of a kept target when that source is gated. The agent logs the targets left out as a too-old console, once per change of their count. `/enroll` precedes every heartbeat response, so it lists only the connectors of protocol 0.1.0; the others appear in the first heartbeat after a response that lists their token. The engines of protocol 0.1.0 have no token and are never left out. The token functions are exhaustive matches, so a new contract engine does not compile until it is given its token.
2. **Result batches are held, not sent.** A findings or events batch whose items carry a gated value (`Location.engine` for a finding, `AccessEvent.source` for an event, every source belonging to one engine) stays in the spool while any of its tokens is not listed. It is sent once a heartbeat response lists them all; a change of the listed set wakes the spool worker. The spool's existing bounds and eviction rules apply to held batches. Other batches are not blocked behind a held one: the worker takes the first sendable batch in FIFO order. The tokens of a batch are recorded in its spool entry when it is written or loaded (the loader parses every file anyway), so deciding that a batch is held never reads its file: the cost per flush is a scan of the in-memory entries, not of the held files. The heartbeat metric `spool_held_batches` (open-keyed `metrics` map, no protocol change) counts the batches held.
3. **A `400` `enum` on a gated-engine item's engine field keeps the item.** When `/findings` or `/events` answers `400` with item pointers, the agent records the items pointed at with the keyword `enum` **on exactly their engine field**: `/findings/<i>/location/engine` or `/events/<i>/source`. An `enum` on any other field (the console answers `/findings/<i>/classifier` with `enum` for an unregistered classifier) is not an unknown engine value, and no later listing of a token would cure it. If the batch carries a gated engine value, the agent:
   - clears the capabilities, as for an unknown field (ADR-0022 decision 9);
   - keeps every rejected item that carries a gated engine value and was pointed at with `enum` on its engine field, under a new `batch_id`; with the capabilities cleared, the new batch is held (decision 2) until a heartbeat response lists the token again;
   - drops the other rejected items by the ordinary rule (an item rejected with `enum` on another field, or for another keyword, is dropped).

   Each such replacement is counted with the stripped batches (`gated_fields_stripped_total`).
4. **Bound: one resend per item.** Gated items are only ever sent after a heartbeat response listing their token. So when a batch whose items were already kept once (decision 3) comes back with the same `enum` on their engine field, the console that listed the token still refuses the value: the items are dropped and counted (`dropped_items`), never held a second time. The mark travels with the batch through splits (`413`) and ordinary item drops; it is kept in memory with the spool entry, not in the file, so an agent restart allows one more attempt. Each item therefore causes at most two rejected requests per agent run, each recorded by the console as an agent-integrity event (`batch_rejected`), so a misconfigured rollout is visible without cycling. Replacements add one level to the spool key; with this bound a gated item uses at most one more level than an ordinary one, far from the spool's key depth bound (`MAX_KEY_DEPTH`, 16), past which a replacement is dropped and counted.

## Consequences
- Rolling upgrades, console rollbacks and mixed replicas lose no item of a new engine: the items wait in the spool instead.
- Every new engine (Microsoft SQL Server, Redis, Valkey, SQLite, Firebird) reuses this mechanism with its own `engine.<value>` token; no further ADR is needed for the pattern, only the token.
- A kept item may be sent again under a new `batch_id` after a console already stored it (lost `202`), as with stripped batches (docs/09).
- Deciding whether a batch is held needs no file read (decision 2). Only batches of gated engines are held, and the console sends jobs only for targets it was told about, so held batches are rare.
- Clearing the capabilities (decision 3) also makes the next heartbeat leave out the targets of the gated engine (decision 1): the console shows them as absent and drops their notes until a heartbeat response lists the token again and the following heartbeat reports them.

### Residual risks
- **Spool fill while a console is older.** Held batches accumulate for as long as the console does not list the token (an agent with a CAS target attached to an old console). They count against `spool.max_bytes` and `spool.max_batches`; when the spool is full, the oldest batch of its class is evicted and counted (`dropped_batches`, `dropped_items`), and held batches, usually the oldest, go first. The agent warns about withheld targets once per change of their count, and `spool_held_batches` shows the held batches.
- **Mixed replicas during a rollout.** With the one-resend bound (decision 4), items of a gated engine that meet a replica refusing the value twice are dropped, even though another replica would have accepted them. ADR-0022 decision 8 (list a token only once every replica accepts the value) avoids it; a deployment that ignores that rule loses those items, counted.
- **The mark is not persisted.** After an agent restart, an item already kept once can be kept once more (one more rejected request per restart).

## Rejected alternatives
- **Strip the value or send a placeholder engine**: not valid against the contract, and a placeholder would attribute a CAS finding to another engine.
- **Persist the kept-once mark in the spool file name**: a new file-name form that an older agent build would quarantine after a downgrade, for at most one extra rejected request per restart.
- **Keep items whatever field the `enum` points at**: an `enum` on another field (an unregistered classifier) is not cured by any listing, so the item would cycle until evicted (P8-C security review M1).
- **Drop the items as rejected**: loses data in every rolling upgrade and rollback, which ADR-0022 decision 9 already refused for optional fields.
- **Hold the whole spool behind a held batch**: one unlisted engine would stop every other engine's findings and events.
- **Split the gated items into their own batch at the first rejection only**: the agent already avoids sending them before the token is listed; holding at the source is simpler and costs no rejected request in the common case.
