# ADR-0029: OpenLDAP connector: client, bind, grants, sampling, locations, Audit through `cn=accesslog` and bulk search detection

- **Status**: Proposed
- **Date**: 2026-09-29
- **Context references**: phase 6 ([ROADMAP](../ROADMAP.md#phase-6--openldap): Discovery, Audit via `cn=accesslog`, bulk search detection), branch `feat/p6-a-openldap` (`agent/crates/connector-openldap`, `agent/crates/core/src/config.rs`, `agent/crates/core/src/audit/own.rs`, `agent/crates/classifiers/src/masking.rs`, `shared/protocol/signals.json`, `shared/protocol/target-notes.json`, `dev/openldap/`, `dev/seed/generate.py`); the OpenLDAP counterpart of [ADR-0026](0026-mongodb-connector.md) / [ADR-0027](0027-mongodb-audit.md) (MongoDB), [ADR-0018](0018-mysql-mariadb-grants-and-connector.md) / [ADR-0023](0023-mysql-mariadb-audit-sources-and-levels.md) (MySQL / MariaDB) and [ADR-0015](0015-postgresql-connector-decisions.md) (PostgreSQL); events follow [ADR-0007](0007-mask-access-events.md), names [ADR-0009](0009-name-normalization-and-item-sanitization.md), correlation [ADR-0021](0021-access-event-correlation.md)

## Context
Phase 6 adds the last MVP engine: find sensitive attributes in an OpenLDAP directory (`mail`, `telephoneNumber`, custom attributes; `userPassword` must never be read) and audit reads through the `slapo-accesslog` overlay, with detection of LDIF exports and bulk `ldapsearch` runs ([docs/08](../08-engine-capabilities.md#known-export-signatures)). The rules of the other connectors apply: read-only and bounded (I4), declared targets only (I5), credentials local (I3), masking before the uplink (I2), rustls only, honest `check()`, closed notes ([ADR-0022](0022-protocol-capability-negotiation.md)).

LDAP raises its own questions:

- **The client.** [03-tech-stack.md](../03-tech-stack.md) planned the `ldap3` crate. Checked on version 0.12.1 with `default-features = false, features = ["tls-rustls-ring"]`: it builds without OpenSSL and its license (MIT / Apache-2.0) is allowed, but
  - its codec has no frame bound: the BER parser waits for as many bytes as the server announces, so a hostile or broken server makes the agent buffer up to the announced length;
  - its decoder panics on malformed input (`tags.pop().expect("element")` on an empty `LDAPMessage` sequence);
  - result errors carry the server's `diagnosticMessage` and `matchedDN` (text that can quote values and entry DNs), and connection errors are logged through the `log` crate by the library itself;
  - the write operations (`add`, `modify`, `delete`, `modifydn`) and SASL mechanisms beyond the ones needed are compiled in;
  - TLS pulls `x509-parser` (with `asn1-rs`, `der-parser`, `nom`, `time`) and `url`.
- **DNs embed values.** Entry DNs name people (`uid=jdoe`, `cn=Jane Doe`, `ou=<a person>`); the contract never lets an entry DN leave the agent (`Identifier`, `ObjectRef`), and the same holds for logs.
- **Passwords live in the tree.** `userPassword` holds hashes (`{SSHA}…`); the scheme is part of the value, so even "hash scheme counts" would need the values.
- **No effective-rights query.** OpenLDAP shows a client neither its ACLs (`olcAccess` is in `cn=config`) nor its effective rights; only what a search returns tells what the account can read.
- **What `cn=accesslog` records**, checked against Debian / Ubuntu `slapd` 2.6.10 with the dev configuration: one entry per operation, written when the operation ends (`olcAccessLogOps: reads writes session`): `reqType`, `reqStart` (the RDN), `reqEnd`, `reqSession` (connection number), `reqAuthzID` (the normalized authorization DN, empty for anonymous and for bind records), `reqDN` (the target or search base as the client sent it), `reqResult`, and per type `reqScope`, `reqFilter` (the filter as a string, **with its assertion values**), `reqAttr` (requested attribute names), `reqAttrsOnly`, `reqEntries` (entries returned), `reqSizeLimit`, `reqMethod` (bind), `reqAssertion` (compare, **with the value**), `reqMod` / `reqOld` (writes, **with values**), `reqControls` (control values, a paged-results cookie for instance), `reqMessage` (server text). Every log entry has an `entryCSN` assigned when it is written, so CSN order is commit order; a long search is written at its end with an early `reqStart`. A paged search gives one record per page, with that page's `reqEntries`. The password modify extended operation is logged as a `modify`. **No client address is recorded.** An `(entryCSN>=…)` filter and `reqDN:dnSubtreeMatch:=` extensible matches work on the log database.

## Decision
1. **Own client for a closed subset of LDAPv3, no library** (as [ADR-0018](0018-mysql-mariadb-grants-and-connector.md) decision 3 and [ADR-0026](0026-mongodb-connector.md) decision 1 did).
   - Operations the client can encode: `BindRequest` (simple, SASL `EXTERNAL`), `SearchRequest`, `ExtendedRequest` for StartTLS (`1.3.6.1.4.1.1466.20037`) and Who am I? (`1.3.6.1.4.1.4203.1.11.3`) only, `UnbindRequest`. There is no encoder for add, modify, delete, modify DN, compare or any other extended operation: read-only by construction (I4). Filters are built in code from closed constructs; console-provided names are never put in a filter.
   - BER is read by the connector's own bounded reader: definite lengths only (at most 4 length octets), low tag numbers only, the `LDAPMessage` length checked against 16 MiB **before** the body is read, fixed nesting (the reader parses the grammar of the responses it expects, never a generic tree), fail closed on anything malformed, buffers zeroized. A response to another message id, an unsolicited notification (message id 0) or an unexpected protocol operation ends the connection.
   - `diagnosticMessage`, `matchedDN` and referral URIs are never kept, logged or sent; only the numeric result code is (contract `EngineCode`).
   - **Referrals and continuation references are never followed** (I5): a `SearchResultReference` is counted (`skipped_remote`), and `derefAliases` is always `neverDerefAliases`.
   - Dependencies: the workspace TLS crates only (`rustls`, `tokio-rustls`, `rustls-native-certs`, `rustls-pki-types`) and `zeroize`. No new license, no MSRV change.
2. **One declared server, TLS by default.** `targets[].openldap.tls`:
   - `verify_full` (default): LDAPS, TLS from the first byte (default port 636), certificate verified against the pinned `openldap.ca_file` (then the only trusted root) or the system store, host name checked (DNS or IP SAN);
   - `start_tls`: StartTLS on the LDAP port (default 389), then the same verification. A refused StartTLS fails the connection (no fallback), and a server that sends bytes between its StartTLS response and the TLS handshake is refused (response injection). Nothing but the StartTLS request is sent in clear;
   - `disable`: an `ldapi://` Unix socket (`socket`) or a loopback IP literal only (never `localhost`).
   - **No `disable_insecure`** for OpenLDAP: a simple bind sends the password itself (unlike SCRAM or `caching_sha2_password`), so cleartext on a network is refused outright.
3. **Authentication: a dedicated service DN, never anonymous.**
   - `openldap.bind: simple` (default): `account` is the service DN, the password comes from its `agent.yaml` reference into zeroized memory. An empty password is refused client-side (RFC 4513 section 5.1.2: a non-empty DN with an empty password is an *unauthenticated* bind that servers may accept as anonymous).
   - `openldap.bind: sasl_external`: SASL `EXTERNAL` over `ldapi://` only (a `socket` target with `tls: disable`), no `secret` (the configuration refuses one): slapd authenticates the agent's Unix uid / gid through the socket's peer credentials, mapped to a DN by the operator's `olcAuthzRegexp`. `account` is then the expected authorization DN.
   - After binding, the client runs Who am I? and requires an authorization identity (`dn:…`): an empty one (anonymous) fails with `authentication_failed`, and with `sasl_external` it must equal `account` (DNs compared case-insensitively, spaces around separators ignored). The normalized DN the server returns is the agent's identity in `cn=accesslog` (decision 9).
   - Not supported: anonymous binds, SASL `PLAIN` / `DIGEST-MD5` / `GSSAPI` / `SCRAM`, client certificates, proxied authorization.
4. **Least-privilege access (`olcAccess`), recommended in [05-security.md](../05-security.md#recommended-database-accounts-read-only):**

   ```
   # Data database: credentials first, then the tree.
   olcAccess: {0}to attrs=userPassword,authPassword by self =xw by anonymous auth by * none
   olcAccess: {1}to dn.subtree="dc=example,dc=org" by dn.exact="cn=databastion,ou=services,dc=example,dc=org" read by * break
   # Log database (Audit only).
   olcAccess: {0}to dn.subtree="cn=accesslog" by dn.exact="cn=databastion,ou=services,dc=example,dc=org" read by * none
   # Result sizes: at least limits.max_sample_rows on the tree, 1000 on the log.
   olcLimits: dn.exact="cn=databastion,ou=services,dc=example,dc=org" size=1000 time=60
   ```

   - **`userPassword` is never readable by the agent and never requested**; neither are `authPassword`, their subtypes, nor a closed list of other credential attributes (Samba NT / LM hashes and history, Kerberos keys, `pwdHistory`, `userPKCS12`), whatever the ACL. **Presence and hash-scheme counts are not reported**: the scheme is inside the value, and granting `search` or `compare` on `userPassword` to make presence visible would turn the account into an oracle on the hashes. Findings on password attributes are therefore never produced for LDAP; the ground truth marks `userPassword` as invisible.
   - `read` on the tree includes `search` and `compare`; `write`, `manage` and `auth` on anything are never needed.
   - `check()` evaluates what a read-only account can see, never by trying a write (I4), with closed notes (decision 11):
     - `privilege.password_attributes_readable`: an attributes-only search (`typesOnly`, `sizeLimit` 1) for entries with `userPassword` or `authPassword` returns one with the type disclosed, so the values would be readable: the values themselves never cross the wire;
     - `privilege.config_readable`: a base search (attributes `1.1`) on the root DSE's `configContext` (`cn=config`) succeeds: the ACLs, the `olcRootPW` hashes and every setting are readable;
     - `privilege.accesslog_without_audit`: `cn=accesslog` is readable while no Audit stream runs for the target (the log holds other users' filters, assertion values and old values);
     - `privilege.write_not_evaluated`, always: OpenLDAP shows a read-only account neither its ACLs nor its effective rights, so write, `manage` and `auth` access cannot be evaluated; the operator checks `olcAccess`.
5. **Discovery sampling (bounded, I4).**
   - The root DSE gives the `namingContexts` (at most 64 read), `subschemaSubentry`, `configContext` and the supported controls; the `cn=accesslog` base (`openldap.accesslog_base`, default `cn=accesslog`) is never scanned. Naming contexts are filtered by the job's `databases` against their normalized name.
   - **Schema.** `attributeTypes` and `objectClasses` of the subschema subentry (RFC 4512 descriptions, at most 4096 attribute types and 2048 classes, 8 KiB each), with `SUP` chains resolved (at most 16 levels). An attribute is requested only when its usage is `userApplications`, it is not a credential attribute (decision 4), and its syntax (inherited through `SUP`) is in a text allow-list: Directory String, IA5 String, Printable String, Numeric String, Country String, Telephone Number, Postal Address, Generalized Time, Integer. DN, Name and Optional UID (group members, `seeAlso`: references to other entries, which are scanned themselves), octet strings, binaries, certificates, JPEG, UUID and any unknown syntax are never requested (fail closed). At most 1024 attributes are requested (by name, sorted); custom attributes are covered like standard ones.
   - **Containers.** Per naming context, one subtree search for the container entries (`organizationalUnit`, `organization`, `dcObject`, `domain`, `country`, `locality`), attributes `1.1` (DNs only), `sizeLimit` 1024; a cut listing counts `skipped_limit`.
   - **Entries.** Per container (and the naming context itself), one one-level search, filter `(objectClass=*)`, the requested attributes plus `objectClass` and `structuralObjectClass`, `sizeLimit` = the job's `sample_rows`, `timeLimit` from the job's statement timeout (at least 1 s), `derefAliases: never`, no paged results (the size limit bounds each search; a server limit below it gives a smaller sample). Entries are grouped by (normalized container, structural object class); per group at most `sample_rows` values per attribute, values cut to 4096 bytes on a character boundary, values that are not UTF-8 skipped, Generalized Time read as `YYYY-MM-DD`, attribute options (`;lang-fr`, `;binary`) stripped and pooled with the base attribute. Each search is read to its end before any finding is submitted: nothing is open on the server across `submit()`.
   - Coverage: `objects_sampled` counts groups; `skipped_not_readable` a container the server refuses (`insufficientAccessRights`, or `noSuchObject` hiding it); `skipped_remote` continuation references; `skipped_limit` cut listings; `skipped_error` any other failure of one search.
   - Sampling order is the server's (entry id order on `back-mdb`, oldest entries first). **Entries under a non-container parent** (`uid=x,cn=group,ou=a,…`) are not read: their parent is not listed as a container.
6. **Locations.** `database` = the naming context, `schema` = the entry's container, `object` = the structural object class (canonical schema name), `field` = the attribute (canonical name, lowercased). The container is the entry's parent DN reduced by `names::normalize_ldap_dn` (leading non-container RDNs dropped; a value that looks like data, a person name for instance, becomes `*`: `ou=Oliver O'Connor,ou=teams,…` is `ou=*,ou=teams,…`); the naming context goes through the same function. Using `schema` for the container is a clarification of the contract `Location` text for OpenLDAP (compatible change). **Entry DNs never leave the agent** and are never logged: logs carry normalized names and counts only.
7. **Audit source: `cn=accesslog`** (`audit_source` `openldap_accesslog`), read over LDAP with the same account and transport. Per poll: one-level searches under `openldap.accesslog_base`, filter `(entryCSN>=<cursor − 10 s>)`, `sizeLimit` 1000, repeated (at most 16 times per poll) while the server cuts the result, then from the newest CSN read. Entries already read in the 10 s overlap are recognized by their CSN (at most 65 536 kept), which covers log writes committed out of CSN order. The cursor (the newest CSN, a server timestamp) is persisted through the core; the first start reads from the agent's clock minus 60 s (no history replay).
   - **Attributes read**: `objectClass`, `reqType`, `reqStart`, `reqSession`, `reqAuthzID`, `reqDN`, `reqResult`, `reqScope`, `reqFilter`, `reqAttr`, `reqAttrsOnly`, `reqEntries`, `reqSizeLimit`, `entryCSN`. **Never requested**: `reqMod`, `reqOld`, `reqAssertion`, `reqMessage`, `reqControls`, `reqRespControls`, `reqData`, `reqReferral`, `reqNewRDN`, `reqNewSuperior`.
   - `reqFilter` and `reqDN` hold other users' values: they are reduced in memory (zeroized buffers) to closed facts, never kept, logged or sent: from the filter, whether it selects entries by value (decision 8) and whether it is exactly one of the agent's own filters (decision 9); from `reqDN`, the naming context it falls under, its normalized container and a keyed 64-bit hash (paged search totals).
   - **Actions**: `search` and `compare` are `read` (`rows` = `reqEntries` for a search, none for a compare); `add`, `modify` (password changes included), `delete`, `modrdn` are `write` (`rows` 1); `bind` is `connect`, or `auth_failure` when `reqResult` is not 0 (except 14, SASL in progress); `unbind`, `abandon` and extended operations give no event. A search that failed but returned entries is reported; any other failed operation is skipped (nothing read or written).
   - **Principal**: `reqAuthzID` (the server's normalized DN), `anonymous` when empty; for a bind, the bind DN (`reqDN`, lowercased, spaces around separators dropped; always fingerprinted on failure by the core), unidentified for a SASL bind (no DN in the record). No client address (the log has none) and no application name.
   - **Objects**: the naming context of `reqDN` (longest match, case-insensitive; `*` when none) and, from the console's `sensitive_objects` of that naming context, those the operation could reach: for a base-scope search, a compare or a write, the objects of the container of `reqDN`; for a one-level search, those of the container `reqDN` itself; for a subtree search, those of `reqDN`'s container name and every container below it (at most 16, sorted). With none, the object is `*` with the container as `schema` (the object class is not in the log). The console's per-object sensitivity and `sensitive_objects` both match these exactly.
8. **Signals** (registered in `shared/protocol/signals.json`, append-only):
   - `shape.bulk_search` (new, `openldap`): a search with scope one-level, subtree or children whose filter selects no entry by value: only presence tests (`(objectClass=*)`, `(mail=*)`) and `objectClass` equality assertions, combined with `&` / `|` (`(&)` included). The LDIF-export shape of docs/08, extended to one-level searches and presence filters (`ldapsearch -s one -b ou=people '(uid=*)'` dumps the container just as well).
   - `volume.large_result` (engines + `openldap`): more than 10 000 entries returned by one search, **or by the pages of one paged search**: the records of one connection (`reqSession`) with the same base (hashed) and scope are summed, and the record crossing 10 000 and the later ones carry the signal (at most 4096 such sums kept, forgotten on unbind or after 1 h).
   - No `signature.*`: `ldapsearch` declares nothing, and `slapcat` (an offline LDIF export on the server host) performs no LDAP operation, so no `cn=accesslog` record.
   These are heuristics: selective filters that match everything (`(uid=a*)` … `(uid=z*)`, `(!(uid=nobody))`, `(cn>=a)`), per-entry base-scope reads, or pages spread over several connections evade them; the volume × sensitivity score remains the robust signal, and it works here (`reqEntries` on every search).
9. **The agent's own account.** As for the other engines ([ADR-0027](0027-mongodb-audit.md) decision 7), an event is left out only when it is a read or a connection of the agent's identity (the Who am I? DN), carries no signal, and the agent's reads of each object stay within `limits.max_sample_rows` entries over a rolling 24 h. The log has no client address and no application name: a new core mode (`ClientSeen::NotRecorded`) makes the address rule not apply, instead of leaving nothing out. The agent's own shapes, compared exactly (own identity, and the filter, scope, base and attribute list the connector sends):
   - container listing (decision 5), the check probes (a base-scope search with attributes `1.1` on a naming context, the password-attribute probe of decision 4, the accesslog proof searches of decision 10): read no attribute value of a data entry; not charged to the budget and without the bulk-shape signal (`routine_unbudgeted`);
   - entry sampling (one-level, `(objectClass=*)`, the explicit attribute list, `reqSizeLimit` at most `max_sample_rows`): charged to the budget, evaluated without the bulk-shape signal; when reported (over budget), reported with it.
   Writes, and anything else with the agent's identity, are always reported.
10. **Levels** (`check()` and the stream use one rule). **Full** when every scanned naming context has a search record (`auditSearch`) in `cn=accesslog` from the last 24 h: `check()` looks for one per naming context (`(&(objectClass=auditSearch)(reqDN:dnSubtreeMatch:=<context>)(entryCSN>=<24 h ago>))`, attributes `1.1`, `sizeLimit` 1), and when there is none, runs one base-scope search on the context (attributes `1.1`) and looks again: a server that logs reads proves it at once. Some contexts proven: **Partial**; none: **Limited** (binds and writes may still be logged), both with `audit.reads_not_logged` (count of contexts). The log not readable (`noSuchObject`, `insufficientAccessRights`, or no such base): **None** with `audit.accesslog_not_readable`. The proof is cached 10 minutes per target; the stream's own search records renew it. Justification of Full: every search is logged with its authorization identity, base, scope and entry count, which is docs/08's definition; what is missing (the client address) is not part of it and is documented.
11. **`check()` notes** (new codes, `openldap`, counts only, no label, so no capability token, [ADR-0022](0022-protocol-capability-negotiation.md) decision 4): `audit.accesslog_not_readable`, `audit.reads_not_logged`, `privilege.password_attributes_readable`, `privilege.config_readable`, `privilege.accesslog_without_audit`, `privilege.write_not_evaluated`; `openldap` is added to the engines of `check.stage_failed`, `check.timed_out` and `audit.records_dropped` (log entries that do not parse, counted for 24 h). The privilege report is recomputed at most every 10 minutes per target. The check uses 3 s per operation and 9 s in total.
12. **Errors** are reduced to a closed failure code, the LDAP result code (contract `EngineCode`) and a closed stage: 49 `invalidCredentials`, 48, 7, 8, 13 are `authentication_failed`; 50 `insufficientAccessRights` is `permission_denied`; 3 `timeLimitExceeded` is `timeout`; 51, 52, 80 and a connection failure are `target_unreachable`; 4 and 11 are `resource_limit` (a size limit ends a Discovery search without error: the entries read are kept); 2, 12, 53 are `unsupported`.

## Consequences
- `agent.yaml` gains `targets[].openldap`: `tls` (`verify_full` / `start_tls` / `disable`), `ca_file`, `bind` (`simple` / `sasl_external`), `accesslog_base`. `secret` becomes optional in the schema, required for every target except `sasl_external` ones, where it is refused.
- The core gains `ClientSeen::NotRecorded` (decision 9) and the classifiers' closed signal set `shape.bulk_search`. The registries gain the codes of decisions 8 and 11; the console regenerates its catalogs (`pnpm protocol:generate`).
- The contract `Location` description states the OpenLDAP mapping of decision 6 (text only).
- docs-keeper: [05-security.md](../05-security.md#recommended-database-accounts-read-only) replaces "to be defined in phase 6" with decision 4; [03-tech-stack.md](../03-tech-stack.md) replaces `ldap3` with the connector's own client; [08-engine-capabilities.md](../08-engine-capabilities.md) gets an "OpenLDAP Discovery / Audit" section and the Full condition of decision 10; the ROADMAP phase 6 items.
- The dev environment keeps its ACL (the service DN reads the tree except `userPassword`, and `cn=accesslog`); the seed gains a custom schema (`databastionContractor`, with a NIR and an IBAN attribute) under `ou=contractors`, to test custom attributes; `make dev-reset dev` reloads it.
- CI gains an `agent-openldap` job mirroring `agent-mongodb`.

### Residual risks
- **Own parser.** BER and LDAP responses from a possibly hostile server are parsed by connector code: bounded and fail closed, exercised by property tests, still code to maintain.
- **Sampling bias and blind spots**: the first entries of each container in server order; entries under non-container parents; attributes with a syntax outside the allow-list; a server size limit below `sample_rows`; the root entry of each naming context itself is not sampled.
- **Credentials of the agent with no address to check**: someone holding the agent's DN and password can bind from anywhere unreported, and read up to the budget per object and day with the agent's sampling shape; the agent's exact container listing and probes are never charged (they return container DNs, at most one DN, or nothing). Writes with the agent's identity are always reported.
- **Heuristic signals** (decision 8), and `olcAccessLogSuccess: TRUE` (only successful operations logged: failed binds are invisible) cannot be seen by the agent; neither can an `olcAccessLogBase` that covers part of a naming context (the proof search may fall inside it).
- **Log gaps**: `olcAccessLogPurge` removing entries the agent has not read yet (agent stopped longer than the purge age); on first start, a server clock behind the agent's by more than 60 s skips records until it catches up.
- **At-most-once delivery**, as for the other connectors.
- **Other users' filters and DNs in memory**: the agent reads `reqFilter` and `reqDN` (zeroized buffers, reduced at once); a compromised agent host holding the service DN's password can read the whole log anyway.

## Rejected alternatives
- **`ldap3`**: see Context. Unbounded frames and a panicking decoder on hostile input, server text in errors and library logs, write operations compiled in.
- **Reporting `userPassword` presence or hash schemes**: the scheme is in the value; a `search` / `compare` grant makes the account a hash oracle; the value adds little (every directory stores password hashes).
- **Reading `cn=config` to evaluate the ACLs**: needs a grant far beyond read-only (the whole server configuration and the root password hash).
- **Probing write access with a real or `noop` write**: breaks the closed read-only operation set (I4); the `noop` control is not even offered by default.
- **`reqStart` as the cursor**: a long search is written at its end with an early `reqStart`, so a cursor on `reqStart` skips exactly the long exports; `entryCSN` follows commit order.
- **Paged results for Discovery**: the size limit bounds each search, and paging would only raise the server's cost and the cookie state kept across `submit()`.
- **One subtree search per naming context for Discovery**: a large container read first would use the whole sample, and the agent's own events would name every object of the tree.
- **`object` = container, `schema` = object class**: aligns with Audit (which never sees the object class) but contradicts the contract's scan filters and coverage counters, which call LDAP objects "objectClasses"; decision 7 gets the same matching from `sensitive_objects`.
- **`disable_insecure`**: a simple bind in clear on a network gives the service DN's password to anyone on the path.
- **Anonymous Discovery**: coverage would depend on what anonymous may read, and the agent's reads could not be told apart in the log.
