# ADR-0023: MySQL / MariaDB Audit sources and levels

- **Status**: Accepted
- **Date**: 2026-09-29
- **Refines**: [ADR-0018](0018-mysql-mariadb-grants-and-connector.md) (which stays Accepted), decision 5 (audit level) and the `performance_schema` part of decision 1; also replaces the `performance_schema` sentence of the [ADR-0020](0020-mysql-mariadb-connector-as-merged.md) "Dev environment" consequence (ADR-0020 stays Accepted)
- **Context references**: P4-B, branch `feat/p4-b-mysql-audit` (`agent/crates/connector-mysql/README.md`, `agent/crates/connector-mysql/src/check.rs`, `agent/crates/connector-mysql/src/audit/`, `agent/crates/classifiers/src/query.rs`, `shared/protocol/signals.json`); the MySQL / MariaDB counterpart of [ADR-0015](0015-postgresql-connector-decisions.md) decision 4 and the P4-A PostgreSQL Audit connector

## Context
[ADR-0018](0018-mysql-mariadb-grants-and-connector.md) decision 5 says that Full "is never reported before the MySQL / MariaDB Audit connector (P4-B): it needs the agent to read an audit log file (`server_audit`, `audit_log`)". Read literally, it implies Full once P4-B lands. Writing P4-B showed that no MySQL / MariaDB source gives what PostgreSQL gives with pgaudit plus a volume source:

- neither the MariaDB `server_audit` log nor the Percona `audit_log` plugin or `audit_log_filter` component logs the rows a statement returned;
- `performance_schema` has row counts but is a ring buffer (statements pushed out between two polls are lost), and the account, client host and `program_name` of a session are only readable while the session is connected.

ADR-0018 also left open how the servers mask passwords in statement text and where the audit log files live and with which file ACL. P4-B measured the first and documented the second. An accepted ADR is not edited, so this ADR records the decisions P4-B implements.

## Decision
1. **Sources and preference.** Three sources, chosen by one rule (`check::choose`) shared by `check()` and the Audit stream:
   - the MariaDB `server_audit` log file (`audit_source` `mariadb_server_audit`);
   - the Percona `audit_log` JSON file, in the plugin's line format or as the `audit_log_filter` array (also MySQL Enterprise Audit JSON) (`mysql_audit_log`);
   - `performance_schema` statement history: `events_statements_history_long`, otherwise `events_statements_history`, otherwise `events_statements_current` (`performance_schema`).

   The audit log is configured per target as `mysql.audit_log {path, format}` in `agent.yaml`, with `format` `server_audit` or `json` and an absolute `path`. The file is used when it is readable by the agent and the matching plugin is active and logs statements in a supported format; otherwise `performance_schema` is used when usable; otherwise there is no source. The XML and CSV `audit_log` formats and the syslog outputs are not supported: the configuration refuses them, and a server writing them is noted by `check()` and not used. The general log is noted and never used as a source.
2. **Levels.**
   - **Full is never reported for MySQL / MariaDB.** Neither audit log gives rows per statement, and `performance_schema` loses statements (ring buffer) and the accounts of sessions that ended before the poll.
   - **File sources are Partial**, and **Limited until the stream has parsed a record of the log in the last 24 h**: the same freshness rule as the P4-A pgaudit source (a readable, configured log that nothing is written to proves nothing). This rule applies to the file sources only.
   - **`performance_schema` is Partial** when `performance_schema` is on, `events_statements_history_long` is enabled with the consumers it depends on (`events_statements_current`, `global_instrumentation`, `thread_instrumentation`) and the account can read it. **Limited** when, with those same dependent consumers enabled, only `events_statements_history` or `events_statements_current` is enabled and readable. **None** when the dependent consumers are off, when nothing is readable, or when `performance_schema` is off. This refines ADR-0018 decision 5, which did not require the dependent consumers (MariaDB leaves `events_statements_current` off by default).
   - The source and level are re-evaluated every 5 minutes while the stream runs.
3. **Privileges.** The audit-log sources need no database grant: the agent reads the file through the file system on its own host, and the plugin probes need no privilege. The `performance_schema` source needs `SELECT ON performance_schema.*` (ADR-0018 decision 1), and nothing else (no `PROCESS`, no global privilege). `check()` treats that grant as the Audit grant, and says nothing about it, while an Audit stream runs for the target; otherwise it reports it as over-privilege (`SELECT on performance_schema without Audit enabled`). The dev agent accounts keep the minimal Discovery grants (`SELECT` on the seeded database only, no `performance_schema` grant); the Audit integration tests create a dedicated account with the `performance_schema` grant.
4. **Statement text.** From `performance_schema`, the connector reads `DIGEST_TEXT` first (literals already replaced by the server) and `SQL_TEXT` only for a statement without a digest. The agent relies on no server-side password mask: measured on the dev images, MariaDB `performance_schema` `SQL_TEXT` keeps passwords in clear, MySQL 8.4 `performance_schema` `SQL_TEXT` and the Percona `audit_log` / `audit_log_filter` logs write `<secret>`, and `server_audit` writes `*****`. Every literal is replaced by the query normalizer whatever the statement. Because the session `sql_mode` of a logged statement is unknown, the normalizer lexes the text with and without `NO_BACKSLASH_ESCAPES` (when it holds a backslash) and with and without `ANSI_QUOTES` (when it holds a double quote); readings that differ keep nothing but the statement kind (fail closed). A statement that does not lex keeps no text and no names. Statement text never leaves the agent (the `AccessEvent` contract has no field for it).
5. **Signals.** `signature.mysqldump`: a whole-table read by a client whose `program_name` is `mysqldump`, `mariadb-dump`, `mysqlpump` or `mydumper`, or carrying `SQL_NO_CACHE`, or in a session that took a consistent snapshot, a global read lock or `LOCK TABLES`, or of a table the session ran `SHOW CREATE TABLE` on. `signature.into_outfile`: `SELECT … INTO OUTFILE` / `INTO DUMPFILE`, flagged even when the server refused it. `shape.full_table_read`: a read without top-level `WHERE`, aggregation or derived table, and without a limit or with a limit above 10 000 rows. `volume.large_result`: more than 10 000 rows returned or affected by one statement, `performance_schema` only. The four are registered in `shared/protocol/signals.json` for `mysql` and `mariadb`.
6. **The agent's own account.** Its statements are left out only when they come from its account, from its client address as the server sees it (`USER()`, read at each re-probe; only an IP literal counts, so a host name such as `localhost` leaves nothing out), with its `program_name` (`databastion-agent`) when the source shows one, carry no signal, and stay within `limits.max_sample_rows` rows per object over a rolling 24 h, as in P4-A. The audit-log sources have no row count, so each statement is charged the whole budget.
7. **DDL and DCL events take no object names from statement text.** Objects come from the table records when the source has them (`server_audit` `TABLE`, `audit_log_filter` `table_access`); names are taken from the text for reads and writes only, because DDL text can hold program bodies that the SQL lexer does not delimit.

## Consequences
- **Answers to ADR-0018's open questions.** Password masking per engine and version, and the location and file ACL of the audit logs, are answered in `agent/crates/connector-mysql/README.md` ("Password masking by engine", "Grants and file access"). The two other open questions (`client_ed25519` / PAM accounts, coverage when `information_schema` hides tables) stay open.
- **ADR-0020 "Dev environment" consequence.** Its "no `performance_schema` grant until Audit (P4-B)" becomes: no `performance_schema` grant on the dev agent accounts after P4-B either; the grant exists only on the test account of the Audit integration tests.
- The console shows at most Partial for MySQL / MariaDB targets, with or without an audit plugin. docs/08 must not promise Full for these engines.
- **No row counts on the file sources.** The console scores an event without `rows` 0 ([ADR-0021](0021-access-event-correlation.md)): on those sources only signatures, shapes and object or principal conditions raise incidents, and `volume.large_result` is never set.
- A file source is reported Limited until the stream parses a record: after the log is configured, after an agent restart (the time of the last record is not persisted), and when nothing was written to the log for 24 h.

### Residual risks
- **The dump heuristic can be evaded**, as heuristic signals are by design. Known gaps listed in the README: `server_audit` with `QUERY_DML` logs no `SHOW`, `FLUSH`, `LOCK` or `START TRANSACTION`, so only the `SQL_NO_CACHE` and program-name rules apply there, and `server_audit` has no `program_name`; `program_name` is set by the client; on `performance_schema`, a session that ended before the poll (a short `mysqldump` run) is reported as an unidentified account, and statements pushed out of the ring buffer between two polls are lost (a wrap is logged).
- **`performance_schema` cursors are held in memory**: after an agent restart, reading starts at the newest statement, and what ran while the agent was stopped is not reported.
- **At-most-once delivery**, as for PostgreSQL: an agent crash within the aggregation window loses the events the cursor has already passed.
- **The audit-log file ACL is the operator's job.** The agent needs read access to the log directory only, never to the data directory; the dev environment's `0644` files are a dev-only convenience.
- **Own-account residual**, as in P4-A: someone holding the agent's credentials on the agent host, spoofing its `program_name` and reading at most the budget per table and day with filtered queries stays unreported. Behind a proxy, every client has the proxy's address.
- **`server_audit` times are local** and converted with the server's time-zone offset read at each re-probe; a DST change in between shifts times until the next re-probe.

## Rejected alternatives
- **Report Full for the audit-log sources**, as ADR-0018 decision 5 implied: they carry no row count, so volume-based detection cannot work on them.
- **Report Full for `performance_schema` with `events_statements_history_long`**: statements lost to the ring buffer and unidentified ended sessions make coverage unprovable.
- **Rely on the servers' password masks**: MariaDB `performance_schema` `SQL_TEXT` holds passwords in clear, and a statement cut at the server's text limit can hold a partial password.
- **Read `SQL_TEXT` for every statement**: `DIGEST_TEXT` already has the literals replaced by the server.
- **Leave the `performance_schema` grant on the dev agent accounts**: the E2E harness checks that the dev account has the minimal Discovery grants only.
- **Edit ADR-0018 or ADR-0020 in place**: the ADR convention does not allow editing an accepted ADR.
