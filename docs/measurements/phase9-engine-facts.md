# Phase 9 engine facts (P9-D measurements)

Facts that [ADR-0051](../adr/0051-sqlserver-connector.md) (SQL Server) and [ADR-0052](../adr/0052-redis-valkey-connector.md) (Redis / Valkey) marked "to verify", measured on 2026-10-14 against the opt-in dev services of P9-D ([dev/README.md](../../dev/README.md)) and throwaway containers of the same images, pinned by digest. These results decide implementation details of P9-A and P9-B; they do not edit the ADRs. Where a result contradicts a decision, the "ADR impact" column states the refinement needed, for the maintainer and the docs-keeper to carry into the ADRs.

Images: SQL Server `mcr.microsoft.com/mssql/server` `2019-latest` (15.0.4500.2), `2022-latest` (16.0.4305.5, CU27 GDR) and `2025-latest` (17.0.5015.4), all **Express** (`MSSQL_PID=Express`, the maintainer's decision until the Developer terms are confirmed), digests as in ADR-0051 decision 9 (unchanged on 2026-10-14); `redis` 6.2.0, 6.2.7, 6.2.24, 7.2.16, 7.4.11, 8.2.10, 8.10.2; `valkey/valkey` 7.2.14, 8.0.11, 8.1.10, 9.0.6, 9.1.2. Probe accounts were throwaway logins with fake passwords; no value from the ground truth was used as a marker.

Accounts, as ADR-0051 decision 4 names them: `min` (minimal variant: `SELECT` on the schemas `crm` and `finance`), `aud` (`min` + `VIEW SERVER SECURITY AUDIT`), `daud` (`min` + `VIEW DATABASE SECURITY AUDIT`), `xe22` (`min` + `VIEW SERVER PERFORMANCE STATE`), `xe19` (`min` + `VIEW SERVER STATE`), `vasd` (`min` + `VIEW ANY SECURITY DEFINITION`), `vsss` (`VIEW SERVER SECURITY STATE`), `ctrl` (`CONTROL SERVER`), `high` (`sysadmin`).
